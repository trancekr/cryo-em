# Cryo-EM HK Wiki 사용 안내

논문 PDF를 넣으면 AWS(Byeori)가 논문마다 노트를 쓰고, 분야별 개요·개념 페이지를 만들고, 질문에 답한다.
모든 작업은 맥미니에서 `hk` 메뉴 하나로 한다.

## 처음 한 번

```bash
cd ~/cryo-em && git pull && bash ~/cryo-em/byeori/hk.sh install
```

- 새 터미널부터 `hk`만 치면 메뉴가 나온다.
- `~/Applications`의 **HK Wiki** 앱을 Dock에 끌어다 둔다. 처음 쓸 때 "Terminal 제어 허용"을 누른다.

## 메뉴

| 번호 | 하는 일 | 비용 · 시간 |
|---|---|---|
| 1 논문 추가 | PDF 폴더나 파일을 창에 끌어다 놓는다. **또는 HK Wiki 앱 아이콘에 끌어다 놓는다** | 편당 약 $0.1 · 30~60분 |
| 2 현재 상태 | 논문 수, 분야별 편수, 노트가 안 생긴 논문, 마지막 페이지 작업 | 무료 |
| 3 분야 정리 | 새 논문의 분야를 Claude Code가 정하고, 보고를 확인한 뒤 반영 | 무료 (Claude Code는 Max 요금제) |
| 4 페이지 만들기 | 바뀐 개요·개념 페이지를 다시 쓴다. 계획을 먼저 보여 주고 묻는다 | 보통 $1~5 · 10~20분 |
| 5 질문하기 | 위키 전체를 근거로 답하고 질문 페이지를 만든다 | 보통 $1~3 (최대 $5) · 5~15분 |
| 6 위키 열기 | 최신으로 맞춘 뒤 브라우저에서 연다 | 무료 |
| 7 이번 달 비용 | Byeori Claude 예산 사용액과 계정 전체 비용 | 무료 |

**논문을 넣은 뒤 순서: 1 → 3 → 4 → 6.** 몇 편만 넣었고 분야가 뻔하면 3·4를 건너뛰어도 노트는 검색·질문에 바로 쓰인다.

## 논문 파일 규칙

- 파일 이름 = `저자_출판연도_짧은제목.pdf` (예: `Herzik_2019_sub100k.pdf`). **연도는 출판 연도.** 이름이 그대로 위키 주소가 된다.
- bioRxiv에서 받은 파일(`2026.10.07.757472v1.full.pdf`)은 이름을 바꾸지 않아도 된다. 넣을 때 DOI로 제목·저자를 찾아 자동으로 바꾼다.
- 보충자료: 같은 폴더에 `<본문 파일 이름>_SI.pdf` (또는 `_SM`, `_supp`). 본문에 붙어 함께 읽힌다.
- 같은 논문을 두 번 넣지 않는다(이미 있는 것은 자동으로 건너뛴다).

## 위키 보는 법

- 왼쪽: **Fields**(분야별 개요와 소주제) · **Questions**(질문과 답) · **Concepts**(개념) · **Papers**(논문 노트). 위 검색창은 제목을 거른다.
- 본문의 파란 링크는 다른 페이지, 회색 점선은 아직 없는 페이지. 각 페이지 맨 아래 "Linked from"은 이 페이지를 인용한 곳.
- 페이지는 AI가 노트에서 쓴 요약이다. 숫자·결론을 인용할 때는 링크된 논문 노트(와 원 논문)를 확인한다.

## 이럴 때

| 증상 | 할 일 |
|---|---|
| 논문 추가 결과가 `fulltext_ready_unclassified` | 논문 신원을 못 찾음. 잡지 인쇄본은 1쪽에 앞 논문이 섞인 경우가 많다 → `AWS-SETUP.md`의 해당 줄 |
| 결과가 `extract_failed` | 스캔 PDF 등. 화면에 나온 OCR 명령으로 다시 |
| 메뉴 4 계획에서 `...-other`가 가장 큼 | 메뉴 4에서 `r`(소주제 다시 나누기). 비용이 크다($8~12). `CURATE.md` 참고 |
| 개념 페이지 내용이 오래됨 | `CURATE.md`의 "개념·개요 페이지 만들기" |
| 예산 알림 메일 | 메뉴 7로 확인. 한 달 보통 $5~15, 대량 추가한 달은 $30~50 |

자세한 설명: `CURATE.md`(분류·페이지), `AWS-SETUP.md`(설치·문제 해결).
